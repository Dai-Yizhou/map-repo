# 共享认知底座（MECHANICS）

> mapcraft（agent 制图）与 mapchat（纯聊天构思）**共用本文件作为唯一的机制认知**，两套 skill 只在工作流上不同。聊构思、聊落地、给方案都必须以本文件为准：**本文件没有的能力 = 游戏配置做不到**，不要凭空想象机制；拿不准的能力归"待开发者确认"。
> 细节 schema 以 `spec.md` 为准（唯一事实源在主仓库），本文件是能力边界的世界观版本。

## 1. 数值体系（UCT）

- 两类作用域：**player**（跟玩家走）与 **region**（跟区域走）。字段集合由每张图在 map-meta 自由声明（如 player 的 money/credit，region 的 pros/env），**图里没声明的字段不存在**。
- 符号写在数据里：付钱为负、收钱为正；同一笔数值可以混合正负（如修碑：-钱 +信用 +区域繁荣）。
- **初始值**：玩家初值来自 map-meta `playerInitial`，区域初值来自 `regions[].initial`。
- **上限**：每个字段可声明 `min/max`。**min 是破产阈值而非扣减下限**（见 §6）；max 是硬上界。
- 给数值参考量级时，先问/看图的初始资金，按比例给建议，不凭空拍数。

## 2. 格子类型与能力（8 类，无其它）

| 类型 | 玩家能体验什么 | 配置能力边界 |
|---|---|---|
| empty 空地 | 什么也不发生 | 只有描述文字 |
| supply 补给 | **经过**或**踩中**触发行为（可各配一个） | 挂 behavior（§5） |
| property 地产 | 买地、升级（租金随级涨）、合租股东；不持股者踩中被收租，股东分红 | price / rent[]（按级）/ upgradeCost[] / maxLevel / maxOwnerCount |
| investment 投资 | 买份额；满足条件时全体股东分红/扣款（不限格子位置触发） | price / maxOwnerCount / investmentTriggers[]（`on` 只能用预定义事件：任意玩家踩 event/monument、股东破产、入昼、入夜） |
| jail 监狱 | 踩中入狱：冷却 + 扣款 | jailCooldown / jailCost |
| transport 传送 | 停靠后可付费跳到指定格 | teleportDestinations[]（目标格 + 付费） |
| event 事件 | 踩中按行为随机结算 | 挂 behavior（§5） |
| monument 纪念碑 | 踩中可选付钱修缮，换收益 | repairCost |

通用字段：id/坐标/名字/描述/出边/所属区域/时区/主题。**任意格子都可被骰子走到（写出边）或藏起来（不写出边）**。

## 3. 行为系统（behavior，挂在 supply/event 上）

- 一个行为 = 多个效果条目；每条有**权重与互斥**：非互斥条目各自独立按权重判定；互斥条目归一后只中一条 → 能表达"30% 全队+5"与"二选一"的混合体。
- 每条效果可做两件事：**数值增减**（对本人/全队/指定玩家）与**传送**（把人送到某格，包括把最近玩家拉过来）。
- 概率、随机、抽奖、"某某触发"都在这里做；**确定性数值联动不在 behavior 做**（那是 §4）。
- 行为只能在 supply/event 上挂——property/investment 等的数值效果走格子自身字段。

## 4. 数值联动（valueModifiers，全局规则）

- 让**价格/租金/升级费/传送费/保释/修复费/投资分红**这类数值**随状态自动变化**：可引用区域字段（繁荣等）、昼夜时刻（白天=0/夜晚=1）、付款方字段、其团队均值与人数、目标格等级与股东数。
- 表达能力 = 算术（加减乘除、取整、上下限 clamp、最值）+ 简单条件（比较、if）——**够写"夜晚租金上浮 25%、股东越多越贵、繁荣地段更贵"这类公式**。
- **做不到**：随机、查最近玩家/排行/距离、跨格"地产集合/垄断"联动——这些留在 behavior（§3）或上报开发者。
- 每个数值字段只允许一条联动规则；对玩家只显示结果不显示公式。

## 5. 昼夜

- 地图可配昼夜周期（分钟）与白昼占比；切昼/夜时可对区域字段施加固定增量（如入夜繁荣 -2）。
- 昼/夜切换本身还能触发投资分红；数值公式可读昼夜时刻做联动（§4）。
- "区域繁荣随时间自动衰减/恢复的节奏"是服务端固定行为，地图**不可配**——构思时可以提，落地前标注待开发者确认。

## 6. 破产（负债式口径）

- 扣款可以**扣成负数**；结算后若数值 < 破产阈值（min）即破产，先结算后判定。
- **主动扣款**（买地/升级/传送/保释）：余额不够时游戏会先提示"这样会破产"，玩家确认才执行——设计"博一把"型决策是被支持的。
- **被动扣款**（租金/税）：无预警全额结算，可能直接扣破产——设计高压地段要考虑这点。
- 破产的连带效果：投资触发器可监听"股东破产"；离线玩家的股东位会被定期清理回收（可配阈值）——**股东位饱和不用靠"禁止离线者持股"这类不存在的机制**。

## 7. 经济周期（税与榜）

- 可配**定期税**（按持有比例征）与**持股税**（按股份量征），含免征线——"惩罚囤地""鼓励流动"的节奏工具。
- 可配**实时榜单**（按玩家/区域字段加权计分）——"繁荣度竞赛""首富榜"类目标可行。
- 地图**不可配**：骰子外的移动方式、交易行/银行等无对应字段的新系统——上报开发者。

## 8. 隐藏内容与彩蛋

- 任何格子都可以藏起来：不出边 = 骰子永远到不了；入口用 ① 传送格付费进入 ② 低概率事件传送 ③ 公式控制传送费（如只对某类玩家便宜）。
- 隐藏格必须有归属区域和名字描述；这是唯一合法的"图外内容"，**没有"条件解锁的格子开关"这类机制**。

## 9. 给构思者的三条硬边界（越界即上报开发者）

1. **只有上面 §2–§8 列的能力**；"我想让格子 A 监视格子 B""连锁商铺集团""玩家间直接交易"——现配置做不到，要么换思路要么报开发者。
2. **不发明字段**：任何"给格子加一个 XX 属性"的想法，先问"这能落进 §2 表里哪个已有能力"，落不进去就归待确认。
3. **随机与确定分工**：概率性 → behavior；确定性公式联动 → valueModifiers；两者不混用同一字段。
